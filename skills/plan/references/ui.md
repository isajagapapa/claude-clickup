# UI plan

A change to how the product looks or feels: layout, styling, components, interactions.

1. **Current vs target**: what the screen looks like now and what it should look like, from the card's mockups or screenshots. List the screens and components affected.
2. **Components**: existing components, design tokens and styles to reuse before writing new ones, with their files.
3. **States**: empty, loading, error, long text, many items, disabled, and permissions that hide parts of the screen.
4. **Responsive and accessible**: breakpoints to check, keyboard navigation, focus order, labels, contrast, and dark mode if the app has it.
5. **Steps**: ordered changes, each one reviewable on its own.
6. **Tests**: component, snapshot or browser tests the project already uses, updated for the new look.
7. **Verify**: compare against the mockup in the running app on desktop and mobile widths, suite passes.
