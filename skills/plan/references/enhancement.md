# Enhancement plan

An existing feature works but should work better: behaviour, UX, performance or limits change.

1. **Current vs desired**: how it behaves now (with file references) and how it should behave after the change.
2. **Affected areas**: files, components, endpoints and screens that change, and who uses them.
3. **Compatibility**: existing data, API consumers, saved settings or URLs that must keep working. Migration if needed.
4. **Steps**: ordered changes, each small enough to review.
5. **Tests**: tests to update and tests to add for the new behaviour.
6. **Measure**: how to show it is better (timings, query count, screenshots, before/after).
7. **Verify**: suite passes and the desired behaviour is visible in the running app.
