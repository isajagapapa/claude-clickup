# Docs plan

Write or fix documentation.

1. **Reader**: who reads it (end users, developers, ops) and what they need to do afterwards.
2. **Files**: docs to add or change, and where they live in the project.
3. **Content**: outline of the sections, examples and screenshots to include.
4. **Accuracy**: commands and code samples to run to make sure they still work.
5. **Review**: who should check it, and links to update elsewhere.
